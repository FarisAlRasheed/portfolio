# QA Report — Section Transition Fade Plays Twice

**Date:** 2026-08-26
**Scope:** Page-to-page transition animation between sections (`/`, `/projects`, `/volunteering`, `/contact`)
**Mode:** Quick QA (focused on the reported double-fade bug + related animation issues)

---

## Summary

The reported bug is **confirmed by code inspection and served-bundle verification**: the fade transition between sections plays **twice** (a visible "double fade") instead of once. The root cause is **two independent, overlapping animation layers** that both animate opacity on the same content, plus a **React StrictMode double-invocation** that replays the mount animation in development.

There are **3 distinct issues** to fix, all in `components/DashboardLayout.tsx` and `app/projects/page.tsx`.

---

## Root Cause Analysis

### Issue 1 — Two overlapping fade layers (PRIMARY — the reported bug)

`components/DashboardLayout.tsx` wraps the page content in **two** opacity-animating layers:

```tsx
<main className={cn(
  "transition-all duration-300 p-6 md:p-12",   // <-- CSS transition on ALL properties
  "md:mr-72"
)}>
  <div className="max-w-4xl mx-auto">
    <AnimatePresence mode="wait">
      <motion.div
        key={pathname}
        initial={{ opacity: 0, y: 10 }}        // <-- framer-motion fade
        animate={{ opacity: 1, y: 0 }}
        exit={{ opacity: 0, y: -10 }}
        transition={{ duration: 0.3, ease: "easeOut" }}
      >
        {children}
      </motion.div>
    </AnimatePresence>
  </div>
</main>
```

- The `<main>` element has Tailwind's `transition-all duration-300`. On navigation, when the new page's content mounts, the `<main>` height/content changes and **CSS transitions the opacity** of the whole main block.
- Simultaneously, the inner `motion.div` runs its own **framer-motion opacity fade** (`0 → 1`).
- Result: the user sees **two stacked fades** — the framer-motion fade plus the CSS `transition-all` fade on the parent — which reads as a "double fade" / not smooth.

**Fix:** Remove `transition-all duration-300` from `<main>` (it is not needed; the framer-motion wrapper handles the transition). Keep only layout classes: `p-6 md:p-12 md:mr-72`.

### Issue 2 — React StrictMode replays the mount animation in dev

Next.js App Router enables **React StrictMode by default** (confirmed in `node_modules/next/dist/docs/.../reactStrictMode.md`: *"Since Next.js 13.5.1, Strict Mode is `true` by default with `app` router"*). `next.config.ts` does not disable it.

In development, StrictMode double-invokes effects/mounts. framer-motion's own source (`framer-motion.dev.js` lines ~8277-8285, 8607-8610) explicitly tracks "StrictMode double-invocation" via a `wasReset` flag. This causes the `motion.div`'s initial `opacity: 0 → 1` animation to **replay** on the same mount, producing a second fade even with a single animation layer.

**Fix (recommended):** Set `initial={false}` on the `AnimatePresence` (or `initial={false}` on the `motion.div`) so the first paint is not animated in dev. This is the standard framer-motion pattern for route transitions and eliminates the StrictMode replay. (Note: this is dev-only; the production build does not double-invoke, but the fix keeps dev behavior identical to prod.)

### Issue 3 — Projects page cards animate on every navigation (minor)

`app/projects/page.tsx` gives each project card its own mount animation:

```tsx
<motion.div
  key={index}
  initial={{ opacity: 0, y: 20 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ delay: index * 0.1 }}
  ...
```

These cards are inside the `DashboardLayout` `motion.div` that already fades the whole page in. So on `/projects`:
- The page-level fade runs (0.3s).
- **Then** each card individually fades/slides in with a stagger (0s, 0.1s, 0.2s delays).

This is a **second, nested fade** on the same content — it contributes to the "not smooth" feel and is especially visible because the page wrapper has already faded in. It also replays under StrictMode.

**Fix (recommended):** Remove the per-card `motion.div` wrapper (or set `initial={false}`) so cards render statically inside the page-level fade. If the stagger is desired, keep it but disable it on first mount via `initial={false}` on the page wrapper.

## Bugs Found

### BUG-1 (High) — Double fade on section transition
- **File:** `components/DashboardLayout.tsx` line 17
- **Expected:** One smooth fade between sections.
- **Actual:** Two overlapping opacity transitions — CSS `transition-all duration-300` on `<main>` + framer-motion `motion.div` fade — produce a visible double fade.
- **Repro:** Navigate between `/`, `/projects`, `/volunteering`, `/contact` in dev. Watch the content area; the fade visibly pulses twice.
- **Fix:** Remove `transition-all duration-300` from `<main>`.

### BUG-2 (Medium) — StrictMode replays mount fade in dev
- **File:** `components/DashboardLayout.tsx` lines 21-31
- **Expected:** Fade plays once on navigation.
- **Actual:** React StrictMode (default on in Next.js App Router) double-invokes the mount, and framer-motion replays the `opacity: 0 → 1` animation (`wasReset` path in framer-motion source).
- **Repro:** Same as BUG-1; the second pulse is the StrictMode replay.
- **Fix:** `initial={false}` on `AnimatePresence` (or the `motion.div`).

### BUG-3 (Low/Medium) — Projects cards animate again inside the page fade
- **File:** `app/projects/page.tsx` lines 45-50
- **Expected:** Cards appear as part of the single page fade.
- **Actual:** Each card runs its own `opacity: 0 → 1` + `y: 20 → 0` stagger after the page fade, adding a second animation pass on the same content.
- **Repro:** Navigate to `/projects`; cards fade in a second time after the page fade.
- **Fix:** Remove per-card `motion.div` or set `initial={false}`.
